Seeded (5-seed, paired-t) coreset ablation on ALOHA / DROID / PushT-real (keep 30%, BC-MLP, RTX 2080), run 2026-07-07/08. Scripts: `experiments/ablation_benchmark.py` (seeded, per-condition `per_seed_mse`) + `experiments/aggregate_ablation.py` (mean rank / W-T-L / oracle headroom). Baselines K-Center/Herding/Facility added on the same behavioral features.

Key results (mean vs-random, mean rank):
- **Diversity-only +29.5%, rank 2.00** — best/tied-best, most consistent, within 1.3pt of oracle (+30.8%). This IS Calibra's diversity stage.
- K-Center greedy +24.0%, rank 2.00 (higher variance: rank-4 on DROID).
- Calibra full (quality+diversity) +24.5%, rank 2.67 — **significantly loses to diversity-only on 2/3** (DROID p=0.003, PushT p=0.001).
- Herding is bad (negative).

Decisions this locks in:
1. **Single-seed runs were misleading** — earlier "quality filter is negative on DROID (−2.4%)" and "K-Center beats Calibra on 2/3" were training-noise artifacts (±10% rel). Always seed + paired-t.
2. **Control-mode (position vs velocity) is NOT the cause** of DROID's quality-filter underperformance — velocity-mode metrics ≈ position within noise. Don't build the per-control-mode fix for this.
3. **Oracle headroom is tiny (+1.3pt)** → do NOT claim adaptive regime-aware selection. See [[paper-framing-decision]].
4. **Actionable: change Calibra's default** from quality+diversity to **diversity-only**, and gate the quality filter behind *detected corruption* (where it helps: synthetic / PushT-injected / L4 in RESULTS.md). Worth ~+5pt on clean data.

Paper framing supported: "observability platform whose coverage selection matches the best published coreset (K-Center) and is more consistent; quality-filtering is corruption-gated" — NOT "best coreset algorithm" and NOT "adaptive selection".

**ACT generalization (2026-07-11, `experiments/act_ablation_benchmark.py`).** Re-ran the whole seeded ablation with the learner swapped BC-MLP→ACT (state-based CVAE action-chunking transformer, chunk 16, same datasets/splits/seeds/selection code — only the policy changes; scored on normalized first-action MSE, comparable scale to BC). **The ranking replicated.** ACT aggregate: Diversity-only rank 2.00 / +26.5% (best fixed, same as BC), K-Center 2.67 / +23.1%, Calibra full 3.00 / +23.7%, Herding worst (−7.5%), Random bottom, Oracle headroom ~2pt. Calibra full again *significantly loses to its own diversity stage on DROID & PushT* under ACT (p<0.001) — the corruption-gated-quality story is architecture-independent. This is the generalization result that unblocks outreach/arXiv: findings are NOT BC-MLP-specific. Results in `results/act_ablation_*.json`, written up in README "Cross-architecture check" subsection. Scope caveat kept explicit: state-based ACT on offline action-prediction error, not image-ACT sim rollout.

**Diffusion Policy added (2026-07-11, `experiments/diffusion_ablation_benchmark.py`, state-conditioned DDPM, same harness).** Third architecture. Rank agreement of the 7-method ordering: BC↔ACT Spearman 1.00, BC↔Diffusion 0.86, ACT↔Diffusion 0.86. Invariants hold under all 3: coverage/diversity+Calibra beat Random, Herding worst, Calibra never sig. worse than K-Center. **Key nuance — the quality filter flips sign by architecture:** drag on deterministic BC/ACT (Diversity-only tops those), but *helps* the diffusion learner (Calibra-full highest avg rank 1.33, beats its own diversity stage on 2/3, p<0.02). Report as observation not mechanism (approved wording template in README). Diffusion evaluated by single-sample first-action MSE (stochastic) → only relative/rank comparisons within diffusion; never cross-policy absolute MSE. Follow-ups added: `--eval-samples` (multi-sample robustness) and `--max-steps`+`--conditions` (equal-compute on 5 key conditions). **Contribution reframed** (user-endorsed): from "here's a pruning algorithm" to "the relative effectiveness of robotics dataset-curation methods is largely invariant across three IL architectures (BC-MLP, ACT, Diffusion)"; Calibra is the platform that enabled the study. Before arXiv: equal-compute check, ideally one rollout-success experiment, README cleanup, paper writing — and STOP adding architectures. See [[claim-honesty-pass]].

**Diffusion robustness checks (2026-07-11) — walked back an overclaim.** Ran equal-compute (`--max-steps 5000`) and multi-sample (`--eval-samples 10`) on the 5 key conditions. Both OVERTURN the single-sample "Calibra full is #1 under diffusion (rank 1.33)" result: under both controls **Diversity-only is the top method under diffusion too** (rank 1.67 in both), and Calibra full significantly loses to it on DROID+PushT (p<0.001) — same quality-filter drag as BC/ACT. So the "quality helps diffusion" nuance was a single-protocol artifact; the robust cross-architecture story is cleaner: **Diversity-only is best-or-tied-best under all 3; quality filter is a drag on clean data under all 3; gate quality on detected corruption.** Equal-compute ALSO showed **Full-dataset's advantage was largely a compute artifact** — its vs-random gap collapses (+59/+14/+36% → +2.6/−6.4/+3.6% ALOHA/DROID/PushT) when optimizer steps are equalized, while the coreset selection ranking is unchanged. README diffusion subsection corrected accordingly. Results: `results/diffusion_equalstep_*.json`, `results/diffusion_multisample_*.json`. Gotcha: `aggregate_ablation.py` needs explicit paths — PowerShell doesn't expand `*.json` globs.
