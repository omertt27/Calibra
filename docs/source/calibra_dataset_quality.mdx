# Dataset Quality with Calibra

This tutorial shows an optional third-party workflow for auditing and curating
LeRobot datasets before policy training using
[Calibra](https://github.com/omerTT/Calibra).

Calibra runs deterministic mathematical estimators — no LLMs, no heuristics —
over your episodes and tells you which ones have quality problems and which are
redundant before you spend GPU time training on them.

<Tip>
Calibra is an independent open-source tool. It is not maintained by the
LeRobot team. Install it separately:

```bash
pip install 'calibra-robotics[lerobot]'
```
</Tip>

## Why integrate with LeRobot?

- **Zero changes to existing datasets** — Calibra reads LeRobot v1, v2, and v3
  datasets directly from the Hub or from a local directory.
- **Fast** — audits a 206-episode dataset in under a second on CPU.
- **Reproducible quality reports** — every metric includes 95% bootstrap
  confidence intervals and is backed by a falsifiable claim with stated evidence.
- **Helps authors before publishing** — identify motion quality issues and
  episode outliers before a dataset revision goes public.
- **Optional** — does not modify the training pipeline or dataset format.

---

## Why data quality matters

A typical 1,000-episode demonstration dataset contains:

- **Jerk spikes** — abrupt operator corrections or communication lag create
  large velocity discontinuities that look like valid training signal to a
  diffusion policy but are noise.
- **Timestamp dropout** — dropped physics steps produce irregular timestamps
  that corrupt temporal metrics in sequence models.
- **Redundancy** — in a 10,000-episode dataset, 60–80% of episodes are
  behavioral near-duplicates. GPU cost scales with volume, not uniqueness.

Calibra surfaces these problems before training starts.

## 1. Audit a LeRobot dataset

`calibra <path>` runs analyzers over your dataset and produces a diagnostic
report with 95% bootstrap confidence intervals.

```bash
calibra lerobot/pusht
```

The following output was produced by auditing 206 episodes (25,650 steps) in
**0.97 seconds on CPU**:

```bash
calibra /data/my_lerobot_dataset/
```

## 2. Detect corrupted or low-quality episodes

Add `--json` to get machine-readable output per episode:

```bash
calibra lerobot/pusht --json > pusht_audit.json
```

The JSON report lists every episode with individual metric values, so you can
inspect outliers programmatically:

```python
import json

with open("pusht_audit.json") as f:
    report = json.load(f)

# Find episodes with jerk spike rate above 5%
bad_episodes = [
    ep for ep in report["episodes"]
    if ep["metrics"]["spike_rate"] > 0.05
]
print(f"Found {len(bad_episodes)} high-jerk episodes")
```

On `lerobot/pusht`, Calibra identifies **27 of 206 episodes** as statistical
outliers — concentrated at the start (warm-up artifacts) and mid-collection
(sync loss events).

## 3. Visualise quality, coverage, and redundancy

`calibra compare` benchmarks your dataset against a reference profile.
Calibra ships reference profiles for pusht, aloha, DROID-100, SO-100, and
BridgeData V2:

```bash
calibra compare /data/my_dataset aloha
```

```
VELOCITY DISCONTINUITY RATE
  Yours:  12.1%
  aloha:   1.3%
  Delta:  +10.8%  ▲  Confidence: HIGH  [n=4 real-hardware aloha datasets]

  Significantly rougher than aloha. If using position commands: investigate
  control noise or abrupt operator corrections.
```

Every comparison is backed by a falsifiable claim in Calibra's Claims Registry,
which tracks the evidence count and confidence tier for each assertion.

## 4. Select a smaller training subset

`calibra prune` removes low-quality episodes first, then applies greedy
max-coverage selection to eliminate near-duplicates while maximising behavioral
diversity.

```bash
calibra prune lerobot/pusht --keep 0.30 --strategy diversity --out pusht_coreset.json
```

```

  CALIBRA PRUNING SUMMARY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Original episodes  : 206
  Quality failures   :  51  (removed in Stage 1)
  Diversity pruned   :  93  (removed in Stage 2)
  Coreset size       :  62  (30.1% of original)
  Method             : quality_filter + greedy_max_coverage
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Stage 1** removes the 51 episodes that fail quality thresholds (high jerk,
timing anomalies). **Stage 2** then selects the 62 most behaviorally distinct
episodes from the 155 that remain, using greedy farthest-point sampling on
action-space statistics. The result is a 30% coreset that maximises coverage
of the original dataset's state-action space.

The output `pusht_coreset.json` contains the retained episode indices. Load it
back with the HuggingFace `datasets` API to filter before training:

```python
import json
import datasets

with open("pusht_coreset.json") as f:
    coreset = json.load(f)

ds = datasets.load_dataset("lerobot/pusht", split="train")
ds_pruned = ds.select(coreset["episode_indices"])
```

The generated report can be used directly before training or before publishing
a new LeRobot dataset revision.

## 5. Add a quality gate to your CI pipeline

`calibra certify` exits non-zero when quality thresholds are violated, making
it easy to wire into a post-collection check:

```bash
calibra certify /data/my_dataset/ --policy diffusion
```

Exit codes: `0` = CERTIFIED, `1` = PROVISIONALLY CERTIFIED, `2` = NOT CERTIFIED.

Example GitHub Actions integration:

```yaml
- name: Certify dataset quality
  run: |
    pip install 'calibra-robotics[lerobot]'
    calibra certify $DATASET_PATH --policy diffusion --json > cert.json
  continue-on-error: false
```

## Supported LeRobot formats

| Format | How to use |
|---|---|
| Hub dataset ID | `calibra lerobot/pusht` |
| HF URI | `calibra hf://lerobot/pusht` |
| Local v2 | `calibra /path/to/dataset/` (requires `meta/info.json`) |
| Local v3 | `calibra /path/to/dataset/` (`codebase_version: v3.0` detected automatically) |
| Local v1 | `calibra /path/to/dataset/` (requires `metadata.json` or `dataset_dict.json`) |

Image columns (`observation.images.*`) are excluded automatically — they never
enter RAM even for multi-terabyte datasets, thanks to a DuckDB column-projection
fast path.
